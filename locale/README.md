# Кастомная локаль `ru_RU_nom.UTF-8` — именительный месяц для waybar

## Зачем
Waybar (v0.14.0, движок форматирования fmt) **не поддерживает** glibc-расширение
`%OB` (standalone/именительный месяц) — при попытке использовать `%OB` модуль
часов рендерится пустым. А стандартный `%B` в ru_RU даёт **родительный** падеж
(«июля»), что уродливо в шапке календаря («Июля 2026»).

Решение: собственная локаль `ru_RU_nom`, идентичная `ru_RU`, но с `LC_TIME`,
где `mon` (используется `%B`) заменён на **именительные** названия из `alt_mon`
(«Январь»…«Декабрь», с заглавной). Тогда `%B` → «Июль».

Модуль часов waybar получает эту локаль через поле `"locale": "ru_RU_nom.UTF-8"`
(поле модуля переопределяет env — проверено). Формат-строки используют модификатор
`L` (`{:L%B}`, `{:L%a …}`) — без `L` fmt форматирует в C-локали (по-английски).

## Установка на новой машине
```sh
sudo cp ru_RU_nom /usr/share/i18n/locales/ru_RU_nom
echo "ru_RU_nom.UTF-8 UTF-8" | sudo tee -a /etc/locale.gen
sudo locale-gen
# проверка:
LC_ALL=ru_RU_nom.UTF-8 date +'%A %a %B'   # -> Четверг Чт Июль
```

Важно: после первой генерации локали **полностью перезапустить waybar**
(`killall waybar; hyprctl dispatch exec 'uwsm app -- waybar'`) — SIGUSR2 не
перечитывает mmap locale-archive, и модуль остаётся пустым до рестарта процесса.

Файл `ru_RU_nom` рядом — готовый исходник локали (копия ru_RU с
переопределённым блоком `mon`).
